# Roborock Storefront — Mock

Faithful Next.js 15 (App Router) implementation of `eec/05-site-build/output.json`. Every external dependency is **stubbed with a clean swap-in point** — no real keys required to run.

## Quickstart

```bash
cd eec/05-site-build/repo
pnpm install   # or: npm install
pnpm dev       # http://localhost:3000
```

Build:

```bash
pnpm build && pnpm start
```

## Cross-skill traceability

This repo is the runtime artifact for:

- **eec/02-product-selection** — SKU IDs, prices, audiences, return windows, subscription/concierge flags, `launch_status` + `launch_date` (drives `<ComingSoonTemplate>` / archived UX)
- **eec/03-brand-identity** — palette, typography, tone, welcome offer, CS tone
- **eec/05-site-build** — routes, env vars, accessibility baseline, analytics writeback whitelist
- **eec/06-tracking** — 13 events, Consent Mode v2, PII hashing, GTM container ID
- **eec/07a-tech-seo** — JSON-LD types, sitemap, robots, noindex, AVIF target
- **eec/03b-legal-pack** — cookie / accessibility / CCPA / Prop 65 / warranty / GDPR / DMCA bodies → `/pages/*` + footer Legal column + header CCPA bar
- **eec/04b-social-proof** — reviews, AggregateRating gating threshold, UGC carousel, press trust bar
- **eec/11b-customer-service** — contact methods, live-chat provider toggle, video tutorials, manuals, parts finder, contact form fields + escalation policy
- **eec/04-creative-factory** — asset production status (`brief|stub|shot|retouched|approved`), shoot brief markdown paths, delivered file paths → `<SmartImage>` consumes via `lib/assets.ts`

Changes to those JSON outputs **should** be reflected here when the corresponding skill re-runs. Today this is manual; the production protocol (per `05.analytics_endpoints.rebuild_protocol`) would have 06 modify only the whitelisted files (`.env.local`, `.env.production`, `app/layout.tsx`, `components/ConsentBanner.tsx`, `lib/gtm.ts`).
